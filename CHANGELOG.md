# Changelog

Log of Manence's public releases. Format based on [Keep a Changelog](https://keepachangelog.com/en/). Numbering stays in **0.x**: the framework is young and its doctrine is still shifting; 1.0.0 will arrive once that doctrine has settled under use by hands other than our own.

## [Unreleased]

## [0.13.0] - 2026-10-05

- **The admin GO: the user's words open the guardrail for one session.** Since 0.12 no GO could let the agent write `.claude/hooks/` or `.claude/settings*.json`: the user had to do it by hand, and in practice people do not (two cores out of four passed 0.12 by having the agent write `settings.json` before the new guard landed, a trick that works once). Modeled on sudo: ordinary GOs stay ordinary words; opening the guard takes a GO one level up: a line of the user's own message that begins with **"admin GO"** or **"GO admin"** (any case; "yes," or "ok," may come first). A mention inside a sentence, in quotes or in code opens nothing, since the words come up whenever the feature itself is discussed. A new hook, `admin-go.sh`, runs on `UserPromptSubmit`, the one text the agent's tools cannot write, and turns those words into a grant for the harness's `session_id` (`.claude/hooks/grants/<session_id>`, format 1, in a folder rule 4 already closes to the agent). `guard.sh` lets rule-4 writes of that session through and traces each one (`guard-files-granted`); the opening is traced too (`admin-go-open`). Scope: the whole session, subagents included (they share its id); the `SessionStart` pass of the same hook removes every grant, except on a compaction, so any new start closes the guard again, a resume of the same session id included. A harness session the agent launches starts too, and so ends the human's GO. Nothing else opens: `rm -rf`, forced pushes and local rules hold. The agent may ask for it: rule 4's refusal now tells it to ask the user "I need an admin GO to write <file> (<reason>). OK?", and says that a plain yes is not one. A new rule 4bis keeps the GO the human's: the agent neither runs `admin-go.sh` nor hands the words to a harness session it launches (`claude -p "GO admin …"`). A prompt carrying a relay envelope (`<cross-session-message>`, `<task-notification>`…), closed or not, grants nothing. `guard.local.sh` is shielded: its output goes to stderr, an `exit` or a tripped `set -e` inside it refuses the call instead of letting it through, and it cannot replace the guard's own functions. Rule 4 also sees `git checkout`/`restore`/`apply`/`rm`/`mv` and `dd of=` on the guarded files. Observed under Claude Code 2.1.289 (2026-10-05): a subagent's prompt fires `SubagentStart`, never `UserPromptSubmit`; in a throwaway core, the same write refused without the words, passed with them (by the shell, the Edit tool and the Write tool on `settings.local.json`, with no harness prompt in bypass mode), and refused again in the next session, where the agent asked for the admin GO in the words the refusal gives it. Codex and Grok carry the event in their binaries; not yet observed there.
- **The guardrail's files leave `permissions.deny`.** A deny outranks every hook, and Claude Code applies `Edit(...)` rules to shell redirections too, so the three `Edit(...)` rules of 0.12 kept the files shut even after an admin GO (observed). `guard.sh` rule 4 holds them alone now, for the file tools and the shell; a hook deny holds in every permission mode, bypass included. The price is a single layer for those files: if the hook cannot run, nothing refuses, which is why rule 4 also refuses removing, moving or un-reading it.
- **An ordinary GO is traced, nothing more.** A message carrying an uppercase "GO" adds a `go` line to the guard trace: the publication GO said at the terminal (Spec §21) leaves a trace, and the guard blocks nothing new on its absence.
- **The signed GO, format frozen** (`verify-go.sh`, for a front desk that signs later). A `go` item signed with `ssh-keygen -Y sign -n manence-go` over seven fields in a fixed order, checked against an allowed-signers file in `.claude/hooks/go-signers`; only the signer holds a secret. Nothing calls it on its own yet. `test-guard.sh` checks it with a throwaway key: signed, tampered, expired, wrong signer.
- **`upgrade.sh`, the "predates" conflict file tells the truth.** When a core already held a file under a name the framework ships for the first time, the plan said "the framework's version waits beside it in `<file>.upgrade-conflict`", but that file was a three-way merge against an empty base, all conflict markers. One core installed it as is: its `test-guard.sh` broke behind a guard that then refused the repair, and the user fixed it by hand (2026-10-05, seen on two cores). The file beside yours is now the shipped organ, byte for byte; `scripts/test-upgrade-predates.sh` (atelier only) checks it.
- **Skills follow the admin GO.** `upgrade` asks for one admin GO for all the touches under `.claude/` instead of handing them over as manual gestures (and still hands them over when the user does not give it), resolves conflicts under `.claude/hooks/` before the new guard or under the GO, never installs a `.upgrade-conflict` unread, and moves a MOS's own guard rules to `guard.local.sh`. `weekly-review` counts the openings (`admin-go-open`, `guard-files-granted`, `go`) apart from the refusals. `skill-craft` names `guard.local.sh` as part of the hard boundary.
- **`lint.sh` and `consignes.sh` speak English** (comments, messages, finding codes: `broken-link`, `missing-type`, `review_when-due`…), with the same behavior: same exit codes, same findings on the same files and lines, in full and degraded mode (compared on the atelier, a real core, a real production and a fixture with every defect). Nothing reads the words: `publish.sh` and CI read the exit code, the skills say "findings". The values the hooks match in files stay as they are (`type: instruction`, `status: deposee`, `published/`).

- **A local extension point for the guardrail.** A MOS with rules of its own used to edit `guard.sh` and re-merge them by hand at every upgrade that touched it; since 0.12 that re-merge also happens outside the agent's tools (this framework's own core, 2026-10-05). `guard.sh` now sources `.claude/hooks/guard.local.sh` when it exists: a file of the core's own that `upgrade.sh` never touches and rule 4 protects like the rest of the folder. It can **add** refusals (`local_file_rules`, called with each path a file tool writes; `local_shell_rules`, called once per command after the shipped rules let it through; each sets `REASON` and `RULE`) and **lift** a shipped rule by name (`GUARD_LIFT="push-main"`, among `rm-rf`, `fork-bomb`, `push-force`, `push-main`). `guard-files` cannot be lifted. A local file that does not parse is skipped with a warning: the shipped rules hold and its lifts do not, so a broken file makes the guard stricter, never looser. Its cases go in `.claude/hooks/test-guard.local.sh` (arrays `local_cases` and `local_edits`), which `test-guard.sh` plays; a shipped case whose rule is lifted is skipped and named. The real case it was built for (a core that allows pushing to main on its private repositories, blocks it toward its website, and fences off its public release tree) fits entirely in the two local files: 98 cases conform, the same decisions as its hand-merged guard.
- **Rule 4 closes three shell forms** on the guardrail's files: `touch` (it creates a file there, such as an empty `settings.local.json`), `mv` naming one of them anywhere (moving `guard.sh` away removes it, and a hook that cannot run lets the call through), and a `chmod` that takes the owner's read bit away (`chmod 000`, `a-r`, `u=wx`: same effect). `chmod +x`, `755`, `go-r` still pass. `test-guard.sh`: BLOCK cases now name the rule they exercise, plus a self-test of the extension point on a fixture (132 cases in all with the admin GO and the signed GO).
- **"Since the last session", a SessionStart hook** (`.claude/hooks/since-last-session.sh`, a new organ, wired next to `consignes.sh`). At the top of a session it says what moved since the last one started, derived from the traces and never written by hand: the core's commits, the inbox items new or changed, the guard trace's new lines (the last one quoted), the workstreams whose `About.md` moved. Nothing moved, nothing printed; it asks nothing and fails open. "The last session" is one small file in the repository's git directory (`.git/manence-last-session`: outside git's tracking by construction, nothing to ignore or commit), rewritten at every start except a context compaction. It would have shown at once that an agent had stopped without a trace (2026-10-04). Idea taken from a practitioner's published notes, 2026-10-05.
- **`upgrade.sh` says whether a local guard exists** (`local guard` lines in the identity section: the file, what it lifts, whether it has cases), and when `guard.sh` itself still differs from the shipped organ, hints at moving those rules into `guard.local.sh`.
- **A routine never carries the admin GO.** A scheduled routine's prompt is written ahead of time and reaches the `UserPromptSubmit` hook like a typed prompt; Spec §12 says it never begins a line with the formula, and the weekly review flags one that does where it can read the prompt.

## [0.12.0] - 2026-10-05

The guardrail guards itself and says when it refuses; the journal has a direction and a way to rotate; the base skills take the fixes of their first month in real use. Nothing in this version adds a permission prompt: a deny refuses, a trace is written without asking, and every new review step is a proposal among the others.

- **The guardrail protects its own files.** The shipped deny list held `sudo`, `rm -rf`, a forced push and the reading of `.env`, and nothing kept the agent from rewriting `.claude/hooks/guard.sh` or `.claude/settings.json` with its file tools — the very gap that let an autonomous agent elsewhere edit the list of its own protected files (reproduced here on 0.11.0, 2026-10-04). `settings.json` now denies `Edit(./.claude/hooks/**)`, `Edit(./.claude/settings.json)` and `Edit(./.claude/settings.local.json)` (one `Edit(...)` rule covers every file-editing tool; Claude Code ignores `Write(...)` rules with a warning, so none is written), and wires `guard.sh` on `Edit|Write|MultiEdit|NotebookEdit` too. `guard.sh` gains a rule 4: file tools in both dialects (Claude/Codex snake_case, Grok camelCase and native tool names, `apply_patch` headers for Codex) and shell writes (redirection, `sed -i`/`perl -i`, `tee`, `truncate`, `rm`/`trash`/`unlink`, `ln`, `cp`/`mv`/`install`/`rsync` onto them) are refused on those files; reading, running and copying *from* them pass, and so does writing another tree's `implementation/mos/.claude/…`. Those files change through `upgrade.sh` or by the user's hand. A deny refuses; it never asks: nothing in this version adds a permission prompt.
- **Every refusal leaves a trace.** `guard.sh` appends one line per refusal to `.claude/guard-refusals.log` (ISO date, dialect and tool, rule, the command cut at 200 characters; `MANENCE_GUARD_LOG` moves it), gitignored, written without asking, skipped in silence when it cannot be written — a refusal is a refusal whether or not its trace lands. `weekly-review` reads it: "N refusals this week, the last on …", a harmless command refused is reported as a false positive to fix, and thirty days without a line means replaying `test-guard.sh`, since a guardrail never seen refusing is not known to work.
- **The `go` gesture, contract only (Spec §21).** A fourth instruction gesture: the operator's explicit GO for a gesture the golden rule holds back (a publication, a push to a public remote, a production deploy, a send), given from the front desk instead of at the terminal, possibly in advance — it replaces a question, never adds one. Fields `cible`, `perimetre`, `valable_jusqua`, `auteur`; `consignes` records it and plays nothing, the session carrying the work plays the gesture within its scope and date and cites the item. Not signed yet, so it is exactly as soft as a GO said at the terminal, and the guard does not block on its absence; the signature is the next step. The "Close" / "Abandon" opening word of a `consigne` is now read in the MOS's working language.
- **`guard.sh` reads pushes by segment.** The force and main/master checks used to read the whole command line: a branch name in a commit message, a `--base main` on a chained `gh pr create`, or a note that mentioned a push blocked the harmless push next to them (five false positives across two installations in ten days). The line is now split on `;`, `|` and `&` (backslash-newline continuations joined first) and only the segments that begin with the git command are examined. Fix from the Déclic installation (2026-09-26); the anchoring on the segment's start added upstream.
- **`test-guard.sh` ships next to the guard** (a new organ, `created` at upgrade): 64 cases, blocked and passed, in a throwaway sandbox that never touches the real trace — pushes by segment, the guardrail's own files through every tool and shell form, the Grok dialect, the refusal trace and its failure mode. A change to the guard is not done until it is green, and one run per harness is the end-to-end observation the shipped `AGENTS.md` asks for before the first risky gesture.
- **`upgrade.sh` names an organ that diverges.** When the new version leaves an organ as the version you had and your file differs from it, the dry run used to say "unchanged — yours stands", which hid a local prototype of a skill the framework had since shipped (2026-09-28). The verdict is now `diverges`, counted apart in the summary, and it is repeated at every run until you keep the file, upstream it, or take the shipped one. Nothing is written.
- **`scripts/log-rotate.py`, the journal's rotation** (a new organ, merged by `upgrade.sh` like the hooks). Standard library only, dry run by default (`--out DIR` shows the would-be files, `--apply` writes): puts `log.md` back in its one order (newest first, a tail appended the other way is detected and reversed), then, above 150 KB, moves whole ISO weeks, oldest first, into `log-archive/YYYY.md` until the log is under 120 KB; the current week and the one before never leave. Every entry is kept byte for byte; the outputs are read back and checked (same count, same hash per entry, order, preamble) before anything is written. Harvested from another installation (2026-09-28: 179 entries archived, 318 KB down to 124 KB, dry run identical to the result).

- **The journal reads one way, and the rule is written** (Spec §4). Entries are prepended under the H1, newest first; "append-only" is gone from the Spec, the shipped `AGENTS.md`, the templates and the Manifesto, replaced by "you add, you never rewrite", because two sessions of one installation read it as "add at the end" and left 141 entries on top and 131 at the bottom (2026-09-28). Every base skill that writes to the journal says where, in one clause.
- **The rotation rule follows real journals** (Spec §8). Trigger over 150 KB; whole ISO weeks archived oldest first down to 120 KB; the current week and the one before never leave; `log-archive/YYYY.md`, same format, same direction; played with `scripts/log-rotate.py` on the user's GO. The year-based rule assumed a journal that holds a year under 150 KB; real installations passed it within a quarter.
- **`lint.sh` checks two structural rules** in standalone mode: an `in-progress/` or `done/` nested below another (Spec §17, one level), and the sizes the Spec bounds (`log.md` over 150 KB, `AGENTS.md` over 200 lines; thresholds movable by environment variable). The weekly review reads them there instead of measuring by hand, and runs the rotation script as a dry run every week, since it also reports a journal written both ways.
- **A measured trim of the identity file** (Spec §9). Once a month, and whenever the budget is exceeded, the review lists the lines of `AGENTS.md` and `CLAUDE.md` that have another home, each with its destination and the line count before and after. The bound had no ritual behind it; now it has one, and it asks nothing on its own.
- **A `CLAUDE.md` reduced to the import may go** (Spec §9): Claude Code reads `AGENTS.md` natively (v2.1.277). The shipped one stays, since it carries Claude Code's wiring.
- **`sommet` leaves the shipped `mos.json`** and the Spec: it placed a connector on a hexagonal map no reader draws any more. A `mos.json` that keeps it stays valid and readers ignore it: no schema change, no migration.
- **`close-work` repairs the links a move breaks**: the links elsewhere in production into the folder's old place, the folder's own links to siblings still in progress, a `resource:` naming the old path. Fixing such a link inside a closed folder is not a rewrite (Spec §16). One close broke two links on 2026-09-28, one of them inside a closed folder.
- **A subagent gets a budget** (shipped `AGENTS.md`, Conventions): a number of tool calls or a duration, and the instruction to stop cleanly with a partial report. Lived elsewhere: 2 h 40 spent on a 20-minute test.
- **A harvested skill goes home as the shipped file** (`Implementation.md` §10): the publication hands it to the MOS where its prototype was born, which replaces the prototype at once; `upgrade` gives that case the fate "already covered".
- **The base skills, reread.** `weekly-review`: sizes from the lint, the rotation proposed whatever the journal's age, where measurement dates live, a `review_when` tied to a dated event that did not happen, skill ages that say nothing right after an upgrade, a success condition that holds when no user is present, `.upgrade-removed/` and the container read for orphans. `outward-watch`: its description points to the watch folder named in the scope page; the substrate is the harnesses the MOS is driven from. The thirty-one minor findings of the 0.10 fresh-context check: one term, **reading criterion**, everywhere including the template; one rule for quoted markers (`skill-craft`: a marker is a meaning written in the working language, a key only when another reader matches it); the dated references of a base skill are checked in this changelog, not in the installed MOS's log; `connect-adapter` numbered 1 to 6; `consignes` routes from any front desk and reads "Close"/"Abandon" in the working language; `kb-ingest` and `kb-lint` follow "the wiki method" without a person's name; `upgrade` pushes the core where a push publishes nothing instead of asking. Checked in a fresh context; routing 8 of 8.
- **The dated failures the base skills cite**, recorded here as `skill-craft` now requires: 2026-08-30, the blind recall test of the outward watch missed its target, a blog the routine's network could not reach (`outward-watch`); 2026-09-27, a model called headless rewrote its answer twelve times to stay within a word range (`skill-craft`); 2026-09-28, a close broke two links, one inside a closed folder (`close-work`).
- **CI**: the validation step of the French install set, retired in 0.10, is gone (it would have failed); `test-guard.sh` runs in the lint job.

## [0.11.0] - 2026-09-28

The upgrade has its skill; three fixes found by the first real upgrades to 0.10.0.

- **An eleventh base skill, `upgrade`.** The script carries the mechanics; the skill carries the judgment: read the dry run, get the user's GO before `--apply`, give each conflict its fate (already covered → dropped; content of the MOS → a page of its knowledge base, pointed to from `AGENTS.md`; guidance useful to every MOS → rewritten in English and filed for upstreaming), confirm with `--resolved`, do the manual touches, leave an `event |` entry. Written from the brief the four cores of the first installation followed on 2026-09-27, each sorting its conflicts the same way before the text existed.
- **`weekly-review` reads the watch folder from the MOS's scope page**, like `outward-watch` below (found by the first real run of the reread review).

- **`upgrade.sh` runs again with the default source on macOS.** bash 3.2 read `$_spec…` (the variable followed by an ellipsis) as one variable name and stopped with `unbound variable`; every variable followed by a non-ASCII character is now braced. Found by the second core upgraded (the first ran under `LC_ALL=C`).
- **`upgrade.sh` exits 0 once no conflict is left**, even when manual touches remain: they are listed for the operator, the script cannot check them, and an exit code 2 on a finished upgrade surprised a caller (reported by the third core upgraded).
- **`outward-watch` reads the watch folder from the MOS's scope page** (default `knowledge-base/watch/`) instead of hard-coding it: a MOS that already keeps its reports elsewhere (the first one did, under a French name) keeps them there. Found at the first real upgrade of a core to 0.10.0.

## [0.10.0] - 2026-09-27

The method for skills, and one language for what the framework ships.

- **A tenth base skill, `skill-craft`, holds the method for writing, reviewing and pruning a skill.** What a description must do (it is the only text the agent reads to decide whether to load a skill, so it is the text to test); the four fates of a prescriptive sentence — a *contract* lives at its reader's home and the skill keeps the link, a *stop* is never pruned, a *criterion* is the gesture of an audit skill, *guidance* enters only with its reason and a dated failure; what "done" means for a gesture (an observable state, a reading gate, a trace); a routing test; the review that may end in retiring a skill. It was played once before shipping, on the nine other base skills.
- **The nine base skills were reread with it.** Four contradictions with their homes are gone (a routing table "in `CLAUDE.md`", a log entry demanded per decision against the log sieve, a stale language policy, a description that captured "look at the inbox" away from the review). Sixty-seven sentences that restated `AGENTS.md`, the Spec or the guard are now links. Twenty-nine pieces of guidance with no reason behind them were removed, one class at a time; a sentence comes back with its dated failure if a real run misses the condition. Every skill now ends with a **Done** section. `kb-lint` has a success condition and a trace. `weekly-review` gains a step on skills (their age in git, the installed copy against the shipped version) and routes deposited instructions to `consignes`.
- **The install set is English only.** A skill is a program: it is written in English and writes its outputs (log entries, About fields, replies) in the MOS's **working language**, declared in `AGENTS.md` under Language (Spec §14). `implementation/mos/fr/` is removed; `BOOTSTRAP.md` asks for the working language instead of swapping files; the French presentation set (`README.fr.md`, `Manifesto.fr.md`, `QUICKSTART.fr.md`) stays. `upgrade.sh` moves a core installed in French onto the English organs: an untouched organ is replaced (`replaced — moved to the English organ`), a locally edited one gets the English file plus its French edits in `.upgrade-conflict`, to re-apply by hand and confirm with `--resolved`.
- **`upgrade.sh --resolved`.** After a hand-resolved conflict that keeps a local change, the rerun no longer replays the conflict forever: `--resolved` accepts the file as it stands once no conflict file or marker remains, and writes the version stamp. A rerun never overwrites a file whose conflict file still exists.
- **The Spec states contracts, the skills carry procedures.** §15, §16, §20 and §21 keep what must hold and point to the base skill for the step-by-step; §17 says it in one sentence: **one level** — `<domain>/in-progress/` and `<domain>/done/`, never deeper; §19 gives the contract of the `chemin` key on the `kb` attachment (relative to the core's root, inside the MOS's container, never above; the reader refuses beyond). §9 names `skill-craft` as the method; §14 states the language rule.
- **`AGENTS.md` (shipped) gains a convention**: before acting inside a system, look at how it is organized — its connector entry, its identity file, what already exists where you are about to write — bounded to what the gesture touches. Skills only carry the path to what there is to look at.
- **`SKILL.template.md` is a skeleton** that points to `skill-craft`; the method has one home.
- **`publish.sh` keeps session identifiers out of the public history**: `--message FILE` prints a commit message stripped of any `…Session…:` trailer, and `--check` blocks on an unpushed release commit that carries one.

## [0.9.0] - 2026-09-22

The channel: a MOS can now be answered from where it is read.

- **A MOS has a human → agent channel, and it is a file.** A new base skill, `consignes`, reads the inbox items with `type: instruction` and `status: deposee` — what the user did from Manence UI: an answer to an `awaiting` entry (a decision, or a "done" with its proof) or an instruction on a workstream (close, abandon, change course, correct, ask; optionally on one of its documents) — acts through the framework's own skills (`close-work` on "Clore"/"Abandonner", the explicit GO it requires), writes the effect into the workstream's About, marks each item `traitee` or `rejetee`, logs one entry per run and commits the core. It never writes to a third party and never sends anything. Spec §21 states the contract; AGENTS.md's "At session start" tells every harness to run it first.
- **A session-start hook points at the inbox.** `.claude/hooks/consignes.sh` (declared under `SessionStart` in the shipped `settings.json`) counts the deposited items and says so at the top of a Claude Code session. It signals; the agent runs the skill. Other harnesses rely on the AGENTS.md line: the file is the channel, the hook only an accelerator.
- **The routines step fetches before it judges.** The weekly review synchronizes the reference (`git fetch`, compare to `origin`) before reading a routine's proof: a routine that runs in the cloud commits its proof there, and a lagging clone would report a silence that does not exist (lived, 2026-09-20).
- **A knowledge base outside the core declares its path.** The `kb` attachment of `.claude/mos.json` may carry `chemin`, the KB's path relative to the core, for a knowledge base kept in a separate repository; readers use it before guessing (`connect-adapter` says when to set it).
- **UPGRADING tells the truth about reruns.** After a hand-resolved conflict that keeps a local change inside a hunk the new version also changed, the dry run reports the same conflict again; the page now says so and tells you to write the stamp yourself, until the script learns to treat "no conflict file left" as resolved.
- **The guardrail's header names a French false positive**: « à la main » in a heredoc commit message next to a `git push` reads as a push to main; write the message with `-F <file>`.

## [0.8.3] - 2026-09-20

A hotfix, found by the first three upgrades.

- **The lint accepts the comment it ships.** `lint.sh` rejected the trailing YAML comment that the workstream template and the 0.8 migration both write on `awaiting: []` — so every migrated or newborn workstream came out as a finding. The `awaiting` checker now ignores an end-of-line comment, on the field and on its entries.
- **UPGRADING says the guardrail reads whole commands**: write the manual touches through a file-editing tool or run a saved script by its path; a heredoc that quotes a forbidden command is refused like the command.

## [0.8.2] - 2026-09-20

The handover before a clear.

- **`checkpoint`, the eighth base skill.** A session ends when its context is wiped, and whatever it held that was never written down ends with it: the threads still open, the decisions still owed by a human, the judgment about which workstream was sound. The skill is the handover, in eight steps. Every live thread goes to `inbox/` with where it stands, what it needs from the user and the next concrete action — that item is the piece the next session reads first. The log gets the entries the conversation never got. The agent memory is brought up to date when the harness keeps one, and skipped without ceremony when it does not, since harnesses differ there. The workstreams are ruled on, `close-work` called when one is delivered. Everything versioned is committed and pushed, the environment is left as it was found, and whatever waits on a GO is **named, never played** — so the next session cannot mistake it for something already decided. The last message before the clear is five lines: where to pick up, what waits on the user, what was pushed, what is still running, what was deliberately left aside. Born in a sister MOS on 2026-09-16, run there for a few sessions, harvested here — the user in place of a name, a CRM or a site in production in place of that system's own connectors, and the memory addressed as something a harness may or may not have.
- **`upgrade.sh` knows the skill you wrote before the framework did.** A good skill is often born in one system and harvested into the framework later, which leaves its home system holding a local file under a name the framework now ships — with no common ancestor to merge against. That case used to read as an ordinary conflict; it now reads as itself, `CONFLICT (local skill predates the shipped one)`, and behaves the same way the rest of the script does: your file is not touched, the framework's version waits beside it as `<file>.upgrade-conflict`, and a human decides what the name means in that system.

## [0.8.1] - 2026-09-20

Housekeeping, and the doctrine harvest of the summer. Nothing changes in the format a reader relies on: Manence UI 0.1 reads 0.8.1 as it reads 0.8.0.

- **`publish.sh --write` now removes, and not only copies.** A file the release carries outside the manifest used to be a `[SAFETY]` finding that blocked the write; it is now part of the **delta** the script curates — `git rm` when the release is a git repo (the history keeps everything), a move into `.publish-removed/` otherwise — and the report names every file removed. The ordering changed with it, because a lot is only coherent as a whole: the 0.8 release retired two images *and* rewrote the README that linked to them, and no order of operations got past the release's own lint, so that curation was done by hand. The gates that read the **release's** state — its lint, the secret scan — now run *after* the batch; the gates that read the **atelier** — its lint, the leak scan, the root organs, version coherence — still gate the write itself. One thing is never removed automatically: an unexpected file that is a **MOS organ** (`log.md`, `SOUL.md`, `STRATEGY.md`, `CLAUDE.local.md`, `.env`, `inbox/`, `knowledge-base/`, `memory/`) stays `[SAFETY]` and `--write` refuses — that is not curation debt, it is something that should never have reached the release.
- **The review measures what drifts too slowly to be noticed.** On its lint pass, `weekly-review` now reads the size of `log.md` and the length of `AGENTS.md`, and reports past **150 KB** and **200 lines** (Spec §9; the rule joins §8). What it proposes for an oversized log is a **rotation** — the entries of a closed year moved to `log-archive/YYYY.md`, same format, still append-only, still one `grep` away — never a summary, never a deletion, and never played on its own. An oversized identity file is not rotated but trimmed: what has quietly become documentation belongs in the knowledge base.
- **The shipped skills are linted in CI.** A new `skills` job runs `claude plugin validate --strict` over both install sets (`implementation/mos/.claude/skills` and `implementation/mos/fr/skills`). A malformed `SKILL.md` frontmatter loads silently degraded, and its failure mode — an agent that never routes to the skill — is invisible to every other test we have. In the same pass, the base skills' `description` fields were rewritten as **routing triggers**: when to call the skill comes first, what it then does comes second.
- **The review can run on its own.** New section in `weekly-review`, English and French: scheduled (a cloud routine, a cron), the review is **signal-only** — it reads, measures and proposes; it corrects nothing, opens and closes no workstream, and touches nothing outside the core. It writes two things: its `review |` entry in `log.md`, and a synthesis pushed where the human will actually read it. It declares itself in `.claude/mos.json` like any other routine and proves itself through `proof_marker: "] review |"` on `log.md`.
- **The watch stops going blind in silence.** `outward-watch` gains two collection rules and a way to check itself, all three harvested from a real failure. A **blocked domain gets a declared fallback** — search-engine excerpts, or a session that can reach the source — the finding is marked "read degraded", and the report's reliability section names the domain *and* the path used: owning up to an unreachable source is not a substitute for reading it. **A number is read at its source, or marked unverified**: when a public API gives both the figure and the list behind it, a movement is explained by what it returns and never by conjecture. And the **blind recall test** checks the organ itself — a human plants a real, deliberately unhandled publication inside the window, the watch runs knowing nothing of it, and its absence from the report is a missed recall that qualifies itself: an access failure or a filter failure, repaired in two different places. The test reads one way only: it proves a gap, never completeness.
- **L4 names the case the products now ship.** The maker ≠ checker law gains the degenerate case it was written against: a run that ends with a self-review, which approves its own work almost every time. The separation has two acceptable shapes only — a checker in a fresh context, or a human (`concept/loops.md`).
- **An audit is valid for a state, not for an artifact.** A verification report is now dated and bound to the exact state it saw; any later edit reopens it or is marked unaudited. And a negative finding — "X does not exist in the reference" — is preceded by a synchronization of that reference and says which state it speaks of: a negative drawn from a partial snapshot looks like proof, and it accuses (Spec §11).
- **The notification at the boundary.** When a delegated chain contains a step the delegate may not cross — a merge, a publication — you either grant that right explicitly or place an outgoing notification at the boundary: silence is not a waiting state, it is indistinguishable from success. The caller then checks the state of the world, not the state of the report; the `awaiting` field is the same boundary written down on the workstream side (`concept/frontiere-dure.md`).
- **A skill states one criterion a machine cannot tick.** The skill template gains a *reading gate* beside its mechanical ones: a rereading under constraint, phrased to be replayed identically, plus the copies to reread — with their path — for each dimension the skill means to preserve. Any quality criterion left implicit disappears within a few dozen runs.
- **Two schools of governance, named.** The hard-boundary doctrine now says where it stands against the managed-allowlist-plus-sandbox school (Anthropic's AI-native SDLC playbook, 2026): an allowlist holds the unanticipated and a sandbox holds the blast radius, while deny rules and hooks hold across harnesses and survive autonomous modes. Neither is the stronger position — two settings of the same cursor (`concept/frontiere-dure.md`).
- **The minimal About is enough to be born.** The open question of 17/08 — should ceremony scale with the stakes? — is settled by keeping the discipline and lightening the record: frontmatter, the goal in one sentence, the next step, and the rest fills in as the stakes grow. The discipline itself still applies to every workstream, since a workstream born wrong is a risk that does not shrink with the stakes (Spec §16, `open-work` EN+FR).
- **The ritual ends on the first workstream.** The first-startup ritual no longer closes on a description of the first gesture but on the gesture itself: `open-work` played with the human, the newborn `About.md` shown, then the sentences to say next time; Manence UI is mentioned once, as an optional separate reader (`BOOTSTRAP.md`).
- **The README shows a Manence OS through Manence UI.** The hero image is back: a running MOS seen through the reader — domains, what is in progress, what is waiting on someone, the knowledge base at the center — on a synthetic dataset, never a real one.

## [0.8.0] - 2026-09-20

The observable MOS.

- **The map retires; Manence UI is the reader.** The `mos-map` skill is gone, and with it the generated HTML snapshot and its two disclosure profiles. What takes its place is not a skill but a separate piece of software: **Manence UI**, its own repository on its own version, local and read-only, which opens a MOS and answers the three questions an operator actually asks — what is in progress, what is already done, what is waiting on a human — with the knowledge base as a graph alongside. The framework keeps what such a reader reads and nothing more: the production layout (§17), the `About.md` contract (§16), and `.claude/mos-map.json`, which loses its cartographic name to become **`.claude/mos.json`** — same content, same `schema: 3`, the machine-readable declaration of this MOS's connectors and routines. An existing system migrates in one gesture: `git mv .claude/mos-map.json .claude/mos.json`. The rule that keeps the two from waiting on each other: the framework versions the format, the reader declares which versions it reads. Seven base skills now — and a MOS stays complete with no reader at all (Spec §19).
- **The declared wait.** A workstream's `About.md` now says in its frontmatter what is waiting on a human, instead of leaving it to be guessed from the prose: `awaiting`, a list of entries carrying `who`, `what`, `kind` (`decision`, a choice only that person can make, or `action`, a gesture only they can perform), `since` — the day the wait was born, not the last reminder — and an optional `blocks`. `open-work` poses the field at birth so its presence is the norm, the working session adds an entry the moment it hits a human decision and removes it once settled, `close-work` asks rather than refuses when something is left (the remainder goes into the `work-close` entry as a traced renunciation), and the weekly review lists the waits older than two weeks, grouped by person. The Spec gains the rule (§16, and §6: a wait is a freshness too), `lint.sh` checks the structure and only the structure — no reader, human or machine, ever infers a wait from the prose.
- **Routines carry their proof.** The MOS's declaration moves to **schema 3**: a routine no longer declares its rhythm in prose but in a closed list — `cadence` is one of `daily | weekly | biweekly | monthly | quarterly` — and it says where the evidence of its running lands: `proof_glob`, the file pattern whose most recent file is the proof, or, with `proof_marker`, the last entry of a file carrying that marker (dated by its `## [YYYY-MM-DD]` heading — that is how `weekly-review` proves itself from `log.md`), plus an optional `grace_days` (default 2). The weekly review gains a **Routines** step that computes the age of each last proof and reports either "proof received N days ago" or "late by N days", and never says **broken**: a proof that did not arrive may mean the routine ran somewhere that commits nothing. A schema 2 file still reads as it stands (Spec §19).
- **The production layout is a contract.** The Spec now says what anything reading a MOS from outside — a reader, an interface, a script — may rely on: `<domain>/in-progress/<slug>/About.md` and its `done/` twin, an `About.md` carrying `type: work`, `status`, `awaiting` and `work_id`, and a folder under `in-progress/` with no `About.md` shown as the badly born workstream it is, never skipped in silence. And what it must **not** assume: that every slug carries the `YYYYMMDD-` prefix (only those born after the rule do), that a workstream's assets follow any layout, or that anything beyond `About.md` is OKF. The contract's version is the framework's own, read in `.claude/manence-version` (§17).
- **A MOS upgrades in place.** Until now the framework could only be *installed*: `install.sh` refuses a folder that already exists, and the weekly review signals a missed version without ever applying it — so three neighbouring systems sat one, two and three versions behind. New **`upgrade.sh <core>`**, dry run by default, `--apply` to write, and never a commit: you reread the diff and commit it yourself. It sorts every organ into three classes and says which one it is playing. The **mechanical** ones — hooks, templates, the seven base skills — are **merged three ways**, your file against the version you had against the version you are taking: local adaptations survive, framework changes arrive, and where both touched the same lines nothing is written — the merged text waits beside the untouched original as `<file>.upgrade-conflict`. The **identity** — `AGENTS.md`, `CLAUDE.md`, `SOUL.md`, `STRATEGY.md`, `settings.json`, `.env`, `log.md`, the knowledge base, the inbox — is **never touched**; what a version expects of it is printed as a list of retouches for human hands. And each version declares its **migrations**, idempotent and announced: 0.8.0 renames `mos-map.json` to `mos.json`, brings it to schema 3 with an empty `proof_glob` per routine, sets the retired `mos-map` skill aside in `.upgrade-removed/` (nothing is ever deleted), and poses `awaiting: []` in every in-progress `About.md`. The version stamp is written last, and only if no conflict is left: a system that half-landed a version is not at that version. [UPGRADING.md](UPGRADING.md) carries the manual half, one section per version since 0.5.0 — the script reads that file to print it.
- **A workstream has a stable id.** `work_id` in the `About.md` frontmatter, equal to the folder name at birth and **never renamed** — closing already moves the folder without renaming it, and the day a folder moves again, what a reader or a neighboring MOS refers to does not move with it. `open-work` writes it at birth; there is **no retrofit**, so workstreams opened before the field simply have none and `lint.sh` says nothing about it.
